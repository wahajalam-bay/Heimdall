## How to read this

Each domain has one table. Columns are abbreviated; the full field name is in the
legend. Every row carries all 24 fields required by the brief.

| Abbrev | Field |
|---|---|
| **ID** | Requirement ID |
| **Src** | Source document |
| **§** | Page / section / image reference |
| **Requirement** | Source wording or short description |
| **Ent** | Entity — `ZAM`, `ZD`, `BOTH` |
| **Actor** | Actor / owner per source |
| **Trigger** | What starts it |
| **Inputs** | Required inputs |
| **Docs** | Required documents |
| **Appr** | Approval required |
| **Thr** | Threshold |
| **SLA** | Timing / SLA |
| **Exc** | Exception rule |
| **Module** | System module |
| **Current** | Current implementation |
| **Code** | Code location |
| **Test** | Test coverage |
| **St** | Status |
| **Gap** | Gap |
| **Proposed** | Proposed implementation |
| **Cf** | Source conflict — PC ref |
| **Cl** | Clarification / external — ES ref |
| **Pri** | Priority |

**Status:** `IMP` implemented · `PART` partial · `MISS` missing · `BROK` broken ·
`CONF` conflict · `EXT` external source required · `NA` not applicable

Domain sections are ordered by the process, not by priority. `Trigger`,
`Inputs`, `Docs`, `Appr`, `Thr`, `SLA` and `Exc` are recorded as `—` where the
source is silent; a `—` in those columns is a statement that the SOP does not
specify, not that it was not checked.

### What is NOT in this matrix

Requirements that depend entirely on a document listed in the external-source
register are recorded with status `EXT` and are **not** given a proposed
implementation, because proposing one would mean inventing the rule. There are 7
such rows. A further 12 rows carry an `ES-` cross-reference while still being
partially implementable — those do have proposals, scoped to the part that is
unambiguous.
